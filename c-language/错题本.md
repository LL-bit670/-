## 第 2 章 · 数据的存储与运算

### 错题 1 ｜ 强制类型转换与除法（float 那组）

**题目**
```
7.0 / 2
(float)7 / 2
(float)(7 / 2)
-7 % 2
```

**我当时怎么想**：以为 `(float)(7/2)` 也是 3.5。

**正解**
```
7.0 / 2      = 3.5     除号任意一边是浮点，整体按浮点除
(float)7 / 2 = 3.5     先把 7 转成 7.0，再除 → 小数保留住
(float)(7/2) = 3.0     括号先算：7/2 是整数除法砍成 3，再转 3.0（小数已丢，回不来）
-7 % 2       = -1      取余两边必须整数；余数符号跟着被除数 -7 走
```

**一句话要点**：强转救不回已经砍掉的小数；`%` 要整数，余数符号随被除数。

### 错题 2 ｜ printf 的 %c 与 %d（ASCII）

**题目**
```c
char c = 'a';
printf("%c\n", c);
printf("%d\n", c);
printf("%c\n", c - 32);
printf("%d\n", '0');
```

**我当时怎么想**：以为 `printf("%d", '0')` 输出 0。

**正解**：`a` / `97` / `A` / `48`
- `%c` 把数值当 ASCII 编号查表看字符；`%d` 直接报数值。
- 同一个 97，`%c` 看是 `'a'`，`%d` 看是 `97`。
- 小写 − 32 = 大写（`'a'` 97 − 32 = `'A'` 65）。
- `'0'`（带引号）是**字符零**，编号 **48**；数字 `0` 才是 0。

**一句话要点**：`%c` 查表、`%d` 报数；大小写差 32；`'0' ≠ 0`。

### 错题 3 ｜ float 与 double 的 0.1 不能比

**题目**
```c
float x = 0.1f;
if (x == 0.1) printf("equal");
else          printf("not equal");
```

**正解**：输出 `not equal`（不相等）。
- `0.1f` 是 float（4 字节），`0.1` 是 double（8 字节）。两个不同类型的"0.1"替身比特位不同，所以不等。
- 浮点数永远别用 `==`，用差值判断：`fabs(x - 0.1) < 1e-6`（需 `#include <math.h>`）。

**一句话要点**：`==` 比的是「两边比特位是否一样」，不是数学上是否相等。

**易混补充：为什么两个"0.1"会不一样（2026-09-19 讲透）**

根子还是「0.1 的二进制是无限循环」（`0.00011001100110011…` 除不尽）。既然循环，**谁装它都得砍**，区别只在"砍在第几位":

| 格子 | 大小 | 尾数位 | 实际存成 |
|---|---|---|---|
| `0.1f`（float） | 4 字节 | 24 位 | `0.100000001490116…` |
| `0.1`（double） | 8 字节 | 53 位 | `0.1000000000000000055511…` |

两边**前 10 位数字一模一样，第 11 位起分叉**。`==` 是一位一位往下比的，撞到不同 → 判「不相等」。

> 类比：抄 `1/3 = 0.333333…`
> - 短本子只抄 4 位 → `0.3333`
> - 长本子抄 8 位 → `0.33333333`
> 两个都叫"三分之一的替身"，都对，但写下来不一样 → 逐字比就不等。

**两个容易踩的追问**

1. **比较时 C 会先把 `x`（float）自动提升成 double**（两边类型必须一致才能比）。但提升只是"后面补 0"，**补不回已经砍掉的那批信息** → 仍然不等。
2. 所以这段实际是**必定不等**，我注释里写"可能不等"是保守说法——按标准 C 的结果是稳定不等，不是随机。

**对比记牢**

| 写法 | 两边是什么 | 结果 |
|---|---|---|
| `float x = 0.1f; if (x == 0.1)` | float 替身 vs double 替身 | ❌ 不相等 |
| `float x = 0.1f; if (x == 0.1f)` | 同一个 float 替身 | ✅ 相等 |

**正确姿势**：浮点永远别用 `==`，改判差值 → `fabs(x - 0.1) < 1e-6`（要 `#include <math.h>`）。

### 错题 4 ｜ 两个 float 的 0.1f 比，反而相等！

**题目**
```c
float a = 0.1f;
float b = 0.1f;
a == b 成立吗？
```

**我当时怎么想**：回答「不成立」（错）。

**正解**：**成立（true）**。a 和 b 都是 float，`0.1f` 字面量在编译时只转换一次，得到同一个替身，比特位一模一样 → 相等。

**对比错题 3**
| 比较 | 两边类型 | 结果 |
|---|---|---|
| `0.1f == 0.1` | float vs double | 不相等 |
| `float a=0.1f; float b=0.1f; a==b` | float vs float | 相等 |

**一句话要点**：`==` 看「两边比特位是否一样」——类型一致才相等；但写代码仍该用差值判断，别依赖 `==`。

### 错题 5 ｜ `++i` 和 `i++` 的区别（自增谁先谁后）

**题目**
```c
int i = 3, j = 3;
int a = i++;
int b = ++j;
```
求 i、j、a、b 的最终值。

**易错点**：分不清每次自增到底"先加还是后用"，常误以为 a 和 b 一样。

**正解**：`a = 3`、`b = 4`、`i = 4`、`j = 4`
- `i++`（后++）：**先用旧值，再自加**。表达式的值 = 3 → `a = 3`；然后 i 才变 4。
- `++j`（前++）：**先自加，再用新值**。j 先变 4；表达式的值 = 4 → `b = 4`。

**一句话要点**：`++` 在前「先加后用」，`++` 在后「先用后加」；`i++` 表达式的值是旧值，`++i` 表达式的值是新值。

**验证练习（我答错了）**
```c
int n = 10;
printf("%d ", n++);   // 我先写的是 "11,10" —— 顺序反了
printf("%d", n);
```
- 我答：`11,10`（错）
- 正解：输出 `10 11`，**n 最后是 11**
- 为什么反了：第一行 `n++` 是**先用后加**——先掏旧值 10 打印，n 才变成 11；第二行打印的已经是变过的 11。所以顺序是 **10 再 11**，不是 11 再 10。
- 钩子：`n++` 在 printf 里，"打印出来的是加之前的"，这一句就够判断。

### 错题 6 ｜ 浮点数的指数形式（e 写法）哪些合法

**题目**：判断下列写法对错
```
(1) 3.2e5
(2) e5
(3) 1.2e3.5
(4) .5e-3
```

**易错点**：不确定 `e` 前后能写什么，容易把指数写成小数、或漏掉 `e` 前面的尾数。

**正解**
```
(1) 3.2e5     ✓ = 3.2 × 10^5 = 320000.0
(2) e5        ✗ e 前面必须有数字（尾数不能省）
(3) 1.2e3.5   ✗ e 后面的指数必须是整数，不能是 3.5
(4) .5e-3     ✓ = 0.5 × 10^-3 = 0.0005（.5 等同 0.5）
```

**两条铁律**
1. `e`（或大写 `E`）**前面必须有数**——尾数不能空着。
2. `e` **后面必须是整数**——指数只能是整数次幂，不能带小数点。

**一句话要点**：`e` 读作「×10 的几次方」；前面要尾数、后面要整数；`.5` 就是 `0.5`。

### 错题 7 ｜ 三位数拆出百位 / 十位 / 个位（十位为什么是两步）

**题目**
```c
int n;  scanf("%d", &n);      /* 输入一个三位整数，如 456 */
printf("%d\n", n / 100);      /* 百位 */
printf("%d\n", n / 10 % 10);  /* 十位 ← 我卡在这 */
printf("%d\n", n % 10);       /* 个位 */
```

**卡点**：不理解十位为什么不能一步 `%10` 或 `/100`，非要写成 `n / 10 % 10`。

**正解**（以 456 为例）
```
个位：456 % 10   = 6    %10 只留最后一位
十位：456 / 10   = 45   先砍掉个位 6，5 露到最右边
      45  % 10   = 5    再夹末位 → 5
百位：456 / 100  = 4    砍掉后两位，只剩百位
```

**通用模板**（要第 k 位，从右数）
```
第 k 位 = n / 10^(k-1) % 10
个位 = n % 10 ｜ 十位 = n / 10 % 10 ｜ 百位 = n / 100 % 10
```

**两个易错点**
- **顺序不能反**：`n % 10 / 10` = 0（先夹后砍，砍没了）；必须 `n / 10 % 10`。
- **`/` 是整数除法**：`456 / 10` = 45（不是 45.6）。扔掉的小数部分正好是被剪掉的个位——这才是技巧成立的原因。

**一句话要点**：`/10` 砍掉末位、`%10` 取出末位；想拿中间某位，先把 `/` 一路退到它变成末位，再用 `%10` 夹出来。

## 第 3 章 · 顺序程序设计

### 错题 8 ｜ printf 语句结尾写成了逗号（编译失败 → 运行区空白）

**我写的代码**
```c
printf("a 是 %d，b 是 %d\n", a, b);
printf("%d - %d = %d\n", a, b, a - b),   /* ← 结尾是逗号，错 */
return 0;
}
```

**现象**：点「运行」后**运行结果区一片空白**，没有任何输出，也没看到报错。

**我当时怎么想**：以为是 `%d` 和值的个数对不上——其实这行 3 个 `%d` 配 `a, b, a - b` 三个值是**对的**。

**正解**：第 2 行 printf 结尾的 `,` 要改成 `;`
```c
printf("%d - %d = %d\n", a, b, a - b);   /* ✓ 分号结尾 */
```

**为什么**：C 里**每条语句必须以分号 `;` 结束**。逗号不是语句结束符 → 编译器判语法错误 → 编译失败 → 没有任何输出。

**区分两个符号**
| 符号 | 作用 | 能结束一条语句吗 |
|---|---|---|
| `;` 分号 | **语句结束符** | ✅ 只有它能 |
| `,` 逗号 | 分隔符（分隔变量、参数） | ❌ 只用来分隔 |

**一句话要点**：一条要执行的指令结尾必须是 `;`；`,` 只在中间分隔东西。这俩键挨着，手一抖就错，且报错信息难懂——写完每行扫一眼结尾。

### 错题 9 ｜ 缺收尾 `}`：报错波浪线为什么压在 `return 0` 上

**我写的代码（漏了最后那个 `}`）**
```c
int main() {
    int a = 5;
    int b = 3;
    printf("a 是 %d，b 是 %d\n", a, b);
    printf("%d - %d = %d\n", a, b, a - b);
    return 0;
    /* ← 这里少了一个收尾的 } */
```

**编译器报错**
```
main.c:8:5: error: expected declaration or statement at end of input
    return 0;
    ^~~~~~
```

**我当时怎么想**：波浪线压在 `return 0;` 下面，以为 `return 0;` 写错了。

**正解（错不在 return 0，是缺 `}`）**
- 报错给的行号/波浪线 = 编译器「**走投无路**的地方」，不是 bug 出生的地方。
- 缺的那个 `}` **根本不存在于文件里** → 编译器没法给一个不存在的字符画波浪线，只能指向它**最后成功读到的真实字符**，也就是 `return 0;` 这一行（列 5 正好是 `return` 的 r）。
- 它的真实意思是：「我从 `{` 开了个块，一路读到文件末尾（end of input），块还没关上，但我没东西可读了。」
- `at end of input` + 波浪线落在最后一行 → **第一反应：数大括号，少了一个 `}`**（通常是最外层 main 的收尾）。

**一句话要点**：缺收尾括号这种病，波浪线永远落在最后一行——这是规律不是随机。报错位置 = 编译器停下的地方 ≠ 错误位置。

### 错题 10 ｜ 把「两行片段」当完整程序跑 → 4 条 error 刷屏

**我干了什么**：把讲解里的两行对照示例直接粘进编译器跑
```c
printf("a = %d\n", a);   // 往外说：把 a 的值显示出来
scanf("%d", &a);         // 往里收：把键盘敲的数，存进 a 的格子
```

**编译器报错**
```
main.c:1:8:  error: expected declaration specifiers or '...' before string constant
main.c:1:20: error: unknown type name 'a'
main.c:2:7:  error: expected declaration specifiers or '...' before string constant
main.c:2:13: error: expected declaration specifiers or '...' before '&' token
```

**我当时怎么想**：以为代码写错了。

**正解**：代码没错，**错在它不是完整程序**。这两行只是"示意片段"，缺了 C 程序的三件套外壳。

**C 程序的固定骨架（背下来）**
```c
#include <stdio.h>      /* ① 头文件：借用别人写好的工具（printf/scanf 都住这儿） */

int main() {            /* ② 主函数：程序从这里开始跑，一个程序必须有且只有一个 */
                        /* ③ 一对大括号：把要执行的语句全包在里面 */

    /* ← 所有语句都写在这个区域里 */

    return 0;           /* 收尾 */
}                       /* ← 这个 } 一定不能丢（见错题 9） */
```

**翻译这 4 条报错**
- `expected declaration specifiers ... before string constant`
  字面：「我期待一个**声明**，结果看到个**字符串**」。
  原因：这两行裸在文件顶层（不在任何 `{ }` 里），编译器以为你在做全局声明，看到 `printf(` 后面的字符串就懵了。
- `unknown type name 'a'`
  编译器把你的 `a` 当成**类型名**去认（因为它还在"找声明"的状态），当然找不到叫 `a` 的类型。
- `before '&' token`：同理，`&` 出现在文件顶层也不合法。

**一句话要点**：**片段 ≠ 程序。** 跑之前先看一眼有没有三件套——`#include <stdio.h>`、`int main() {`、结尾 `}`。看到 `expected declaration specifiers` 这类"顶层报错"，第一反应就是：**我的语句是不是没包进 `main` 里。**

### 错题 11 ｜ 变量没声明就用 → `'a' undeclared`

**我写的代码**（壳搭对了，但语句区里直接用 `a`）
```c
#include <stdio.h>

int main()
{
    printf("a = %d\n", a);   /* ← 没声明 a 就直接用 */
    scanf("%d", &a);
    return 0;
}
```

**编译器报错**
```
main.c: In function 'main':
main.c:5:23: error: 'a' undeclared (first use in this function)
    5 |    printf("a = %d\n", a);
      |                       ^
main.c:5:23: note: each undeclared identifier is reported only once for each function it appears in
```

**我当时怎么想**：壳补上了就以为能跑了。

**正解**：**C 里变量必须先"声明类型"才能用**。补上声明即可：
```c
int a, b;      /* 一行声明两个；也可以写 int a; int b; */
```

**为什么必须先声明**（想清楚就再也不会忘）
- 电脑给你分配内存格子之前，得先知道两件事：**这个格子多大**（`int` 占 4 字节）、**怎么解释里面的 0/1**。
- 类比：进宿舍要先登记床位——"我要一个 int 大小的柜子，名字叫 `a`"。登记完，管理员（编译器）才知道往哪儿放东西。
- `int a, b;` 里的 `,` 是**分隔符**（分隔两个变量名），不是语句结束符，所以结尾还是要 `;`（呼应错题 8）。

**翻译报错**
- `'a' undeclared`：不认识 `a` —— 你在用名字之前，从没告诉我 `a` 是什么。
- `(first use in this function)`：这是**这个函数里第一次**用到它。
- `note: ... reported only once`：同一个未声明的名字**只报一次**，别以为报错少就只有一个错。
- `In function 'main'`：报错发生在 `main` 函数内部（和第 10 条"顶层报错"正好区分——**有这句 = 壳搭对了**）。

**顺带发现的第二个坑：语句顺序反了**
`printf("a = %d\n", a);` 写在 `scanf` **前面**——`a` 还没被赋值就打印，输出的是**内存里的垃圾值**（随机数）。
正确顺序是 **先 `scanf` 收数 → 再 `printf` 显示**。

**一句话要点**：变量用前先声明（`int a, b;`），声明放函数开头；再看一眼顺序——**先收后显**，别先显后收。

### 错题 12 ｜ 输入里加逗号 → 第二个数读不进来，变量变垃圾值

**我干的**：OnlineGDB 跑 `ch3_scanf.c`，第二段提示后敲了 `4 ,6`（两个数中间用**逗号**）

**代码**
```c
int a, b;
scanf("%d %d", &a, &b);
printf("a = %d, b = %d\n", a, b);
```

**实际输出**
```
Please input two integers (split by space): 4 ,6
a = 34, b = 1232222584
Input a and b to sum: 34 + 1232222584 = 1232222618
```

**问题**：`b` 变成了 `1232222584` 这种怪数，后面还拿它去算加法。

**正解**：输入必须是 `4 6`（中间**一个空格**），或者 `4` 回车 `6`。**不能有逗号。**

**为什么**（scanf 扫描输入的过程）
- `%d` 读完 `4` 后，格式串里的空格让 scanf 跳过空白字符；但下一个字符是 `,`，**不是数字**。
- 第二个 `%d` 转换失败 → scanf 立即返回，**`b` 根本没被赋值**。
- `b` 从未赋值 → 保持**未初始化的垃圾值**（那格内存里残留的 0/1），所以是 `1232222584`。每次运行可能不一样。
- 第三段 `scanf` 同样读不到数（输入区已空，遇到 EOF），直接跳过 → a、b 维持原值 → 算出 `34 + 1232222584`。

**铁律：scanf 格式串里写什么，输入就得照着敲什么（照镜子）**
| 格式串 | 输入必须长这样 |
|---|---|
| `scanf("%d %d", &a, &b)` | `4 6` 或 `4`⏎`6`（空格 / 回车分隔） |
| `scanf("%d,%d", &a, &b)` | `4,6`（**必须**带逗号，加了逗号就得输入也带） |
| `scanf("%d", &a)` | `4` |

**一句话要点**：输入格式必须和格式串严格对齐；scanf 遇到不匹配的字符就**停止**，没被赋值的变量是**垃圾值**，不是 0。

### 错题 13 ｜ 字面量后缀 `f`：`3.14159f` 那个 f 是什么，能直接贴在小数后面吗

**我的疑问**：`3.14159f` 里的 `f` 是啥，小数后面能直接跟字母吗？

**正解**：能。`f` 叫**字面量后缀**，紧贴在小数后面（**中间不能有空格**），作用是**指定这个数就是 float 类型**。

**为什么必须写**：C 有条默认规矩——**带小数点的数字，你不指定就一律当 double**（8 字节），不是 float（4 字节）。
```
3.14159    → double
3.14159f   → float
```

**不写 f 会怎样**：变量声明的是 float，字面量却是 double → 先按 8 字节算，再硬塞进 4 字节格子 → **丢精度**，编译器还可能提示 `conversion from 'double' to 'float'`。能跑，但类型不干净。

**能跟谁**（呼应错题 6 的 e 写法）
| 写法 | 合法 | 说明 |
|---|---|---|
| `3.14159f` | ✅ | 加 f = float |
| `3.0f` / `0.5f` | ✅ | 错题 4 里的 `0.1f` 就是这个 |
| `3f` | ❌ | 整数没小数点，f 被当非法后缀；要写 `3.0f` |
| `1e5f` | ✅ | 指数形式也能加 f |

**验证实验**（runoob 就能跑，不需要键盘输入）
```c
#include <stdio.h>
int main() {
    printf("3.14159  size = %d bytes\n", (int)sizeof(3.14159));
    printf("3.14159f size = %d bytes\n", (int)sizeof(3.14159f));
    return 0;
}
```
输出 `8` 和 `4` —— 亲眼看见 f 把盒子从 8 字节砍成 4 字节。

**别和 `%f` 搞混**
| 写法 | 位置 | 作用 |
|---|---|---|
| `%f` | 写在 printf/scanf 的**引号里面** | 格式说明符，告诉函数"按 float 读/打" |
| `f` | 写在**数字后面** | 字面量后缀，指定这个数的类型 |
两者目标一样（都是 float），但**出现的位置完全不同**。

**一句话要点**：小数不带 f 默认是 double；变量是 float，字面量也陪一个 f，两边类型才对齐。

**易混补充（讲完才懂）**
- **f 不是必须，只是更干净**：直接写 `3.14159`（double）也完全能跑——赋给 float 变量时编译器自动砍成 float，结果一样对。f 只是省掉那一步隐式转换、避免编译器警告。只有"两边类型要一致"的场景（如 `float x; if (x == 0.1)` 应写 `0.1f`）才真正需要 f。
- **4 字节 ≠ 4 位小数**：float 的 4 字节 = 32 位 = 1 符号 + 8 指数 + 23 尾数；23 位尾数约能精确表示 **6~7 位十进制有效数字**。`3.14159` 是 6 位有效数字 → 装得下，所以能打出 3.14159。打印出几位由 `%f`（默认 6 位）/ `%.2f`（2 位）控制，和存了几字节无关。真"装不下"的反例是 15 位有效数字（如 `3.14159265358979`），float 只能保住前 ~7 位。

### 错题 14 ｜ 把"算式"写进 printf 的引号里 → 只打出一串文字，算都不算

**我写的代码**（加练：求各位数字之和，自己写的）
```c
int n;
scanf("%d", &n);
printf("hundreds = %d\n", n / 100);
printf("tens     = %d\n", n / 10 % 10);
printf("units    = %d\n", n % 10);
printf("int sum  =hundreds+tens+units");   /* ← 我写的，错 */
```

**我想干嘛**：把三个数字加起来，输出各位数字之和（输入 456 应出 15）。

**我错在哪**（三个问题叠在一起）
1. **整条算式写进了引号里** → 引号里的内容一律**原样打印**，不参与计算。屏幕只会吐出 `int sum  =hundreds+tens+units` 这串字。
2. **`hundreds`/`tens`/`units` 根本不是变量** → 它们只出现在前几行 printf 的**引号里**当提示文字，从没被声明、也没存值。C 不认识它们。
3. **没有 `%d`、没有逗号后面的值** → printf 不知道要打什么、往哪填。

**正解**（两种写法，任选）
```c
/* 写法一：直接在 printf 里算 */
printf("digit sum = %d\n", n / 100 + n / 10 % 10 + n % 10);

/* 写法二：先声明变量存起来，再打 */
int sum;
sum = n / 100 + n / 10 % 10 + n % 10;
printf("digit sum = %d\n", sum);
```

**核心区分：引号内 vs 引号外**
| 位置 | 是什么 | 例子 |
|---|---|---|
| 引号**内** | 给用户看的**死文字**，原样打印 | `"units = %d\n"` 里除 `%d` 外全是文字 |
| 引号**外**（逗号后） | 真正要算 / 要填的**活值** | `n / 100`、`sum` |

**一句话要点**：**printf 引号里只放"要显示的文字 + `%d` 占位符"，真正的计算和变量放在引号外的逗号后面。** 变量想用必须先 `int sum;` 声明；提示文字不是变量。

**✅ 闭环（2026-09-19 13:20）**：改用「写法二」重跑，输入 `456` → 输出
```
hundreds = 4
tens     = 5
units    = 6
digit sum = 15
```
exit code 0。**加练自写部分过关**，第 3 章正式收工。留下的经验：**引号内是文字、引号外才是值**——写 printf 时先问自己"这行里哪些是要算的活值"。
